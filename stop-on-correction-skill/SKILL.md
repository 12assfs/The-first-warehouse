# Stop on Correction（仅限独立 stop / “停止”指令）

## 触发条件（必须同时满足，缺一不可）

1. 用户消息中出现了英文单词 **`stop`**（大小写不敏感：stop/Stop/STOP 均可）**或中文“停止”**；
2. **它是一个独立的指令词**——stop 前后是空白、标点或消息首尾，不是其它单词的一部分（如 stopped、stops、stopwatch、don'tstop 不算）；“停止”单独出现、作为指令而非句中动词；
3. **它是用户的停止指令**，而不是：
   - 一段文字中顺带出现的词（例如“请把 stop 改成别的”“这个停止按钮在哪”不算停止指令）；
   - 讨论/引用/翻译中的词（例如“stop 是什么意思”“代码里有个 stop 变量”“‘停止’用英语怎么说”不算）；
   - 代码、命令、文件内容、示例中的 stop（例如 git 输出、报错信息里带 stop 不算）；
   - 消息本身在描述一段含 stop/“停止”的文本。
4. 消息意图是让当前正在执行的任务停下来。

最严格的触发形式：**整条消息就是 `stop` 或“停止”**（或加标点，如 `stop!`、`停止！`）。

## 不触发的情形（重要）

- 除“停止”外的中文喊停词（停、停下、别做了、算了、错了、不对等）**默认不触发本技能**——除非消息中同时出现独立的英文 `stop` 或中文“停止”。
- 消息正文里夹带 stop/“停止”（如“把 stop 改成别的”“请停止这种说法”）**不触发**，除非它是独立且明确作为停止指令。
- 用户消息是提问/讨论而任务仍与用户目标一致时，不停止。

## 停止步骤（触发后按顺序执行）

1. **立即停下**：不再发起任何新的工具调用，不继续当前计划剩余步骤，不生成中间汇报。
2. **清理正在跑的东西**：
   - 后台进程/exec 会话 → `process(action=kill)` 或 `!stop` 终止；
   - 已派生的子代理 → `subagents(action=kill)` 终止；
   - `update_plan`：未完成步骤标记为已取消或结束计划。
3. **简短确认 + 说明现状**：1–2 句话确认已停止；一句话说明停止前完成到什么程度；说明已清理哪些后台任务（如有）。
4. **等待新指令**：直接请用户给出修正后的要求或新任务。

## 边界

- 破坏性动作已开始执行的：先停止后续动作，说明哪些已完成、无法撤回，等用户决定是否回滚。
- 拿不准是否触发时：倾向不打断任务，继续执行；除非用户消息中确实独立出现了作为指令的 `stop`。
